从规则到哲学：七条设计轴

七条设计轴从提示词规则出发，解释每款 Agent 被塑造成怎样的行动者、如何分配注意力与权限，以及把哪些资源视为稀缺。以下结论均为基于原文结构的编辑推断，并非厂商自述。

AXIS 01

受托关系

Codex 明确延续会话授权；Claude Code 与 Kimi Code 同时要求完整交付和范围约束。坚持完成与尊重范围可以并存；MiMo 当前标题角色则有更窄的终点。

依据：Codex CLI L9 · Claude Code L67 · Kimi Code L47 · MiMo Code L3
AXIS 02

环境可读性

DSH 区分工作区、实现目录与正在运行的页面；OpenClaw 区分节点、Gateway 和用户会话。路径存在、工具可访问和模型已经看过是不同事实。

依据：DeepSeek Harness L5 · DeepSeek Harness L7 · OpenClaw L2158
AXIS 03

上下文经济

Antigravity 先读紧凑轨迹，Pi 按需加载文档；opencode 要求大块读取。批注把这些视为不同的成本取舍，不据此断言哪种策略在所有任务中更好。

依据：Antigravity CLI L99 · Pi L25 · opencode L85
AXIS 04

记忆制度

Claude 保存代码无法推导的背景；Hermes 按信息寿命分流；OpenClaw 用身份与记忆文件续接；opencode 将偏好放入 instruction 文件。持久保存的位置也影响未来权限和上下文成本。

依据：Claude Code L44 · Hermes Agent L15 · OpenClaw L337 · opencode L116
AXIS 05

证据闭环

Kimi Code 要求验证实际交付，Grok 强调真实浏览器交互，OMP 区分作业退出与产物验收。一次工具成功只证明对应步骤，不能自动证明整项任务完成。

依据：Kimi Code L49 · Grok Build L50 · Oh My Pi L976
AXIS 06

权限与风险

授权来源、持续时间与作用域须分别检查。Codex 与 Kimi Code 承认持续授权，Kimi CLI 此捕获仍要求 Git 修改逐次确认；标签、worktree 和忽略文件规则都不能自动等同于安全沙箱。

依据：Codex CLI L9 · Kimi Code L43 · Kimi CLI L56 · Grok Build L865 · Oh My Pi L776
AXIS 07

协作拓扑

干净上下文、fork、通知型与显式收集型任务各有交接方式。父代理仍需理解需求、收集结果和验证交付；子代理数量与任务已经完成之间没有必然关系。

依据：Codex CLI L221 · DeepSeek Harness L559 · OpenClaw L4554 · Grok Build L858

五个主题，一场横向对照

把 14 份提示词拆进同一坐标系后，浮现出的共识与分歧

目标机器

GOAL · 80 处批注

完成标准可以是完整工作产物、受控目标状态，也可以是一个忠实的短标题。Codex、DSH 与 OpenClaw 暴露目标工具；Hermes 要求真实执行证据；MiMo 当前捕获则必须返回结构化标题。范围约束与持续推进共同定义交付。

依据：Codex CLI L583 · DeepSeek Harness L31 · Hermes Agent L8 · MiMo Code L49

工程纪律

ENG · 139 处批注

验证方法随产物而变：真实场景、构建测试、浏览器交互、落盘哈希分别证明不同事情。Antigravity 同时强调功能与视觉完成度，Pi 强调原始文件匹配；这些规则须连同例外和运行配置理解。

依据：Kimi Code L49 · Grok Build L78 · Hermes Agent L1079 · Antigravity CLI L29 · Pi L19

人格

PERSONA · 54 处批注

Codex 用坦率和可纠正的判断描述协作者；OpenClaw 借 SOUL 与初始化流程表达连续身份；MiniMax 用 Mavis 命名；Pi 的表述更简短。这些是提示层的角色设计，不能证明模型有主观体验或某种商业动机。

依据：Codex CLI L31 · OpenClaw L441 · MiniMax Code L7 · Pi L3

安全边界

SAFETY · 103 处批注

本地可逆操作、外部发消息、产品更新与凭据处理拥有不同授权条件。OpenClaw 通过受保护存储传递秘密引用，Kimi Code 不允许换工具绕过拒绝；权限标签与真实执行边界仍需由宿主实现。

依据：Codex CLI L13 · OpenClaw L3977 · Kimi Code L27

工具·多智能体

TOOL · 196 处批注

独立调用可并行，前提依赖应顺序完成。Codex 的 exec、Hermes 的持久 Python 内核与 OMP 的 workpool 提供不同编排形式；通知、投递回执、可解析结果和验收通过是不同状态。

依据：Codex CLI L117 · Hermes Agent L363 · Oh My Pi L614 · MiniMax Code L1138
