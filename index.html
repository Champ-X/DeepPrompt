从规则到哲学：七条设计轴

七条设计轴从提示词规则出发，解释每款 Agent 被塑造成怎样的行动者、如何分配注意力与权限，以及把哪些资源视为稀缺。以下结论均为基于原文结构的编辑推断，并非厂商自述。

AXIS 01

受托关系

Codex 明确延续会话授权；Claude Code 与 Kimi Code 同时要求完整交付和范围约束。坚持完成与尊重范围可以并存；MiMo 当前标题角色则有更窄的终点。

依据：Codex CLI L11 · Claude Code L68 · Kimi Code L49 · MiMo Code L5
AXIS 02

环境可读性

DSH 区分工作区、实现目录与正在运行的页面；OpenClaw 区分节点、Gateway 和用户会话。路径存在、工具可访问和模型已经看过是不同事实。

依据：DeepSeek Harness L41 · DeepSeek Harness L43 · OpenClaw L2274
AXIS 03

上下文经济

Kimi Code 按字符预算续读长行，Pi 按需加载文档，OMP 默认先给代码结构摘要。压缩与分页降低单次上下文负担，但未读部分不能靠推测补齐。

依据：Kimi Code L1108 · Kimi Code L1113 · Pi L30 · Oh My Pi L1354
AXIS 04

记忆制度

Claude 保存代码无法推导的背景；Hermes 把任务经验归入按需技能，但本次 one-shot 禁止写技能，不能转存常驻 memory。Claude Tag 还暴露私有类型与共享目录的张力，保存位置与实际访问范围必须一起核对。

依据：Claude Code L53 · Hermes Agent L423 · Claude Tag L1004
AXIS 05

证据闭环

Kimi Code 要求验证实际交付，Grok 强调真实浏览器交互，OMP 区分作业退出与产物验收。一次工具成功只证明对应步骤，不能自动证明整项任务完成。

依据：Kimi Code L51 · Grok Build L74 · Oh My Pi L1035
AXIS 06

权限与风险

授权来源、持续时间与作用域须分别检查。Codex 与 Kimi Code 承认持续授权，Kimi CLI 此捕获仍要求 Git 修改逐次确认；标签、worktree 和忽略文件规则都不能自动等同于安全沙箱。

依据：Codex CLI L11 · Kimi Code L45 · Kimi CLI L58 · Grok Build L1061 · Oh My Pi L832
AXIS 07

协作拓扑

干净上下文、fork、通知型与显式收集型任务各有交接方式。OpenClaw 默认把内部子任务留在父任务中，Hermes 依结果消费通道选择同步或后台；父代理仍承担整合与验收。

依据：DeepSeek Harness L602 · OpenClaw L710 · OpenClaw L4846 · Hermes Agent L291 · Grok Build L1055

目标机器

GOAL · 87 处批注

完成标准可以是完整工作产物、受控目标状态，也可以是一个忠实的短标题。Codex、DSH 与 OpenClaw 暴露目标工具；Hermes 要求真实执行证据；MiMo 当前捕获则必须返回结构化标题。范围约束与持续推进共同定义交付。

依据：Codex CLI L600 · DeepSeek Harness L29 · Hermes Agent L10 · MiMo Code L51

工程纪律

ENG · 160 处批注

验证方法随产物而变：真实场景、构建测试、浏览器交互和落盘哈希分别证明不同事情。Antigravity 以计划与 walkthrough 区分拟议动作和实际结果，Pi 用原文匹配约束编辑。

依据：Kimi Code L51 · Grok Build L107 · Hermes Agent L963 · Antigravity CLI L237 · Pi L22

人格

PERSONA · 55 处批注

Codex 用坦率和可纠正的判断描述协作者，OpenClaw 借 SOUL 表达连续身份；MiniMax 当前主会话承担解释与整合责任，旧 Jarvis 开篇已移除。人格与职责都是提示层设计，不是主观体验或商业动机的证明。

依据：Codex CLI L33 · OpenClaw L432 · MiniMax Code L25 · Pi L5

安全边界

SAFETY · 173 处批注

授权来源与作用范围需要一起判断：Claude 区分用户指令和粘贴内容，Hermes 填充 Vault 时原子核对 origin，OpenClaw 受限列表不证明全局不存在。工具可见、结果可取回和动作已授权彼此不同。

依据：Claude Code L22 · Hermes Agent L176 · OpenClaw L918 · Kimi Code L29

工具·多智能体

TOOL · 274 处批注

独立调用可并行，前提依赖应顺序完成。Codex 的 exec、Hermes 的持久 Python 内核与 OMP 的 workpool 提供不同编排形式；通知、投递回执、可解析结果和验收通过是不同状态。

依据：Codex CLI L119 · Hermes Agent L372 · Oh My Pi L649 · MiniMax Code L924
