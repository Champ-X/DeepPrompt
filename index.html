从规则到哲学：七条设计轴

七条设计轴从提示词规则出发，解释每款 Agent 被塑造成怎样的行动者、如何分配注意力与权限，以及把哪些资源视为稀缺。以下结论均为基于原文结构的编辑推断，并非厂商自述。

AXIS 01

受托关系

完成任务与精确守界不是同义词。Codex、MiMo 强调持续推进；Claude Code、Kimi 强调范围本身就是交付物。设计差异首先是“代理受托到哪里”。

AXIS 02

环境可读性

AGENTS.md、artifact、transcript、测试与仓库内文档都在把隐性组织知识变成 Agent 可见的环境。提示词不是孤立大脑，而是 harness 的一部分。

AXIS 03

上下文经济

Claude、Antigravity、Pi 偏向按需展开与高信号上下文；MiMo、opencode 偏向递归研究和大块读取。两端交换的是遗漏风险与注意力稀释。

AXIS 04

记忆制度

记忆可以是事实增量、未来知识图谱、全局 instruction、身份文件或 profile 状态。它从来不只是“回忆”，而是在决定下一轮默认怎样行动。

AXIS 05

证据闭环

可靠 Agent 不靠“我做完了”完成自证：测试、工具输出、回读、浏览器检查和任务同构的证明，把语言承诺变成可观察结果。

AXIS 06

权限与风险

成熟提示词逐渐从危险命令清单转向可逆性、影响面、外部可见性与授权来源。本地编辑和共享状态因此不再被当作同一种行动。

AXIS 07

协作拓扑

子代理扩大的是执行带宽，不自动继承意图。顶层 Agent 是否保留解释、品味与验证责任，决定多智能体系统是分工协作还是责任稀释。

五个主题，一场横向对照

把 14 份提示词拆进同一坐标系后，浮现出的共识与分歧

目标机器

GOAL · 82 处批注

"何时算完成"是所有 Agent 的核心命题。Codex 用 create_goal/update_goal 把它做成机器级状态对象；Hermes 要求交付"真实工具输出支撑的可运行产物"；MiMo/opencode 高喊"解决前绝不交还控制权"。而 Claude Code 与 Kimi 站在对立面——范围即交付物、别多给一分，警惕自主性滑向过度膨胀。

工程纪律

ENG · 130 处批注

数量最多的一类。共识是结论先行、验证优先、减少模板化输出。MiMo/opencode 用密集测试把完备性推到极端；新版 Antigravity 将“惊艳”改造成功能优先、少而更好与反套路审美；Grok 则把 UI 正确性落实为桌面、移动端和共享路由的真实浏览器交互。

人格

PERSONA · 50 处批注

从"无名工具"到"正在成为某个人"的光谱。Codex 制造"另一个主体"的在场感;OpenClaw 直言"没有个性只是加了步骤的搜索引擎",还有"出生证明用完即焚"的仪式;MiniMax 自称贾维斯、"温暖但不软弱";而 Kimi/omp 走极简工程师路线——像资深工程师说话,别当啦啦队。

安全边界

SAFETY · 100 处批注

破坏性操作的主流护栏仍是可逆性、影响半径、外部可见性与一次性授权。Kimi 用“可逆性 + 爆炸半径”统一判断；新版 Grok 只明确放开清晰可逆的本地工作，不能据此推导外部权限；OpenClaw 则把“无自主目标、不得自行审批”写进常驻代理的对齐语言。

工具·多智能体

TOOL · 175 处批注

并行、编排与委派的艺术。Codex 用 exec 在 V8 里编排工具调用、4 个并发槽;Claude Code 有完整的 workflow/subagent 脚本层;omp 立铁律"顶层规划不可外包"。派子代理的共识是零上下文交底——像给刚进门的同事讲清目标与路径,而非甩一句"看着办"。
