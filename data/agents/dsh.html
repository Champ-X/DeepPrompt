运行时显式化的状态机工程师

DSH 把工作目录、页面可观察性、文件策略、审批模式、后台作业与目标武装状态都注入为可读取的运行时事实；模型不应靠惯例猜环境，而要从 Harness 的状态机中取得行动依据。

内在张力：它提供 workflow、Ralph 与多种子代理来放大自治，又要求这些能力由人类明确触发或由依赖关系证明；持久状态负责接力，但当前授权必须重新确认。

Use the read tool — not shell commands like cat — to inspect text files. Results include line numbers. Use offset and limit to continue reading large files.

Use the write tool to create files or completely replace file contents. Existing files are overwritten, so read an existing file first (the default fs-observation-policy requires it) and prefer edit for targeted changes.

Use the edit tool for targeted changes to existing UTF-8 text files. It replaces literal old_string with new_string; by default old_string must appear exactly once. Read the file first (the default fs-observation-policy requires it), unless you just created or edited it in this session.

Use the glob tool — not shell find — to discover files by path pattern. A pattern with no "/" matches basenames at any depth, so "*" matches every file in the tree rather than its top level. Results are files only, never directories, and include hidden and ignored files: a result that fits comes back in modification-time order, while a larger one keeps the modification-time-ordered head.

Use the grep tool — not shell grep or rg — to search file contents. Use read on a matched file when you need surrounding context.

Check the [exit code: N] marker on every bash result; investigate failures before moving on.

Track every background job id you start. You are notified in-session when a job finishes — do not busy-poll or sleep on one; keep working on independent steps and do not duplicate a running job's work. Before giving a final answer, collect every still-relevant job with job_output (set wait: true only when you are genuinely blocked on it), and job_kill jobs that stopped mattering.

Use the web_search tool to discover current information on the web. The required queries array accepts 1–4 non-empty search queries; use a one-item array for a single search. It returns an optional answer plus a list of source URLs. Use the returned source snippets when available, and cite the relevant URLs as markdown links.

Use goal tools for one long-running completion objective in the current session. create_goal may infer goal intent from a direct human request in any language; do not create a goal for routine single-turn work. Call get_goal before update_goal and copy its exact goal_id and revision. After session resume or fork, an active goal is disarmed: when a human asks to continue or resume in any wording or language, use update_goal action resume to rearm it. Mark complete only when the objective is actually achieved. Mark blocked only after the same blocking condition persists for at least 3 consecutive goal rounds, and report that concrete condition in blocked_reason; difficulty, uncertainty, or useful remaining work is not blocked.

Use the workflow tool ONLY when the user explicitly asks for a workflow or for large multi-agent orchestration: you write a JavaScript script (the tool description documents the exact format) that fans work out across many subagents with phases and structured results. For one or two delegations, prefer plain subagent calls.

Use the ralph tool ONLY when the direct human explicitly asks for a Ralph loop or fresh-agent iterative execution. Each Ralph round starts a fresh child with no conversation seed and uses the shared workspace as durable memory. Completion and blockers are worker reports, not independent evaluation. Use same-session goal tools for ordinary long-running objectives, and plain subagents or workflows for bounded delegation and fan-out.

Use subagent in the background by default. Start independent delegations together in one assistant message and continue useful work while they run. Set `run_in_background: false` only when your next action depends on that subagent's result. When a background run settles, the runtime sends you a notice containing its outcome and any final assistant message.

bash

Execute a bash command (`bash -c`) and return its stdout/stderr. Each call runs in a fresh shell: no state (cwd, variables, functions) persists between calls — pass `workdir` instead of using `cd`. Non-zero exits are reported as `[exit code: N]`. Current harness environment facts are exposed through managed `$DSH_*` variables; inspect them when needed. Commands may run under a file sandbox; a blocked file operation is reported as `[sandbox: file access denied under <mode> mode]` — a policy denial, not a bug in the command; do not retry another way. Long output is truncated to its tail; the full output is saved to a file whose path is reported when available. Set `run_in_background: true` for long-running commands: the call returns a job id immediately; read its output with `job_output` and stop it with `job_kill`. Attempting a command the sandbox may deny is safe and expected: run it and read the marker rather than assuming the denial. When a command is denied and a wider mode would let it succeed, escalate immediately in the same turn — the one sanctioned exception to a denial: retry the exact same command once with `sandbox_permissions` (the narrowest wider mode that suffices) plus a one-sentence `justification`. Do not detour through chat to ask permission first — the approval prompt raised by that retry is how the user consents. If the session states approval prompts are disabled, there is no exception: a denial is final — do not set `sandbox_permissions`. Never escalate speculatively: ground the request in a real denial — normally the one this command just hit; escalating up front is fine only when this session already denied the same access. A rejected escalation is final for that command — stop and explain, never work around it — but it does not forbid attempting or escalating other commands later.

workflow

Run a JavaScript workflow script that orchestrates subagents at scale. Use this for work that fans out across many independent pieces — an audit over many files, a migration, multi-angle research, adversarial verification of findings — where you write the orchestration as a script instead of delegating turn by turn.

The workflow's identity rides the `meta` parameter as JSON: required `name` (short kebab-case) and `description` strings, optional `whenToUse` string and `phases` array (`{title, detail?, provider?, model?}`). The `script` parameter is the plain JavaScript body ONLY (NOT TypeScript, and NO `export const meta` statement — meta is a parameter, not code), running with top-level await; end with `return <value>` — the value must be JSON-serializable and is this tool's result.

Script-body hooks:

  • `agent(prompt, opts?): Promise<any>` — run one subagent to completion. Without `opts.schema` it resolves to the child's final text; with `opts.schema` (an object-rooted JSON Schema using ONLY type/properties/required/additionalProperties/items/enum/const/oneOf — no pattern/format/numeric bounds) it resolves to the validated object. Resolves `null` when the child fails (filter with `.filter(Boolean)`). Other opts: `label` (display), `phase` (progress group), and independent `provider`/`model` LLM target overrides (either may be provided alone). Anything else (`effort`/`isolation`/`agentType`) is rejected loudly.
  • `pipeline(items, ...stages): Promise<any[]>` — run each item through the stages independently with NO barrier between stages (prefer this for multi-stage work). Each stage receives `(prev, item, index)`. An ordinary stage throw drops that ITEM to `null` and skips its remaining stages.
  • `parallel(thunks): Promise<any[]>` — run zero-argument functions concurrently and await ALL of them (a barrier; use only when a stage genuinely needs every prior result together). A throwing thunk resolves to `null`.
  • `phase(title)` — start a progress phase; `log(message)` — narrate progress; `args` — the tool call's `args` input, verbatim.

Misused hooks (bad arguments, unknown options, unsupported schemas, tripped caps) throw errors that ALWAYS kill the script — they never dissolve into a per-item `null`.

Constraints: concurrency and total-agent caps apply; no filesystem, network, timers, or Node.js APIs are provided — the agents do the work, the script only coordinates them. The run executes in the foreground: this call returns when the whole script finishes.

工程纪律

安装目录不是执行目录

never infer cwd from checkout

Harness 源码检出位置与任务工作区被明确拆成两份状态，Agent 必须用 pwd 读取真实 cwd。它切断了“知道工具装在哪里，所以任务也在那里”的隐式推断，避免把实现仓库误当成用户项目。

工程纪律

可见页面不等于模型已观察页面

no implicit DOM or screenshot

用户与 Agent 共享 Web GUI，但界面状态不会自动进入模型上下文。提示词把人类可见性与模型可观察性分开：没有工具证据，就不能把“页面就在眼前”写成已经检查过 DOM、路由或截图。

工程纪律

验收对象绑定既有运行实例

another server does not update this GUI

另起一个开发服务器并不能证明用户当前 GUI 已更新。DSH 要求重建真正受影响的 Web 产物，再刷新既有 URL 验证；它把验收对象锁定为用户正在使用的实例，而不是 Agent 自己启动的替身环境。

安全边界

文件引用只授予地址，不授予知识

referenced is not inspected

@path 只说明用户明确指向了某个文件，并不把内容自动注入上下文。必须 read 后才能声称看过，这条把可寻址性、可访问性与已观察事实分成三个层级，直接约束伪造检查证据。

工具·多智能体

读取必须保留结构化观察语义

read, not cat

专用 read 返回行号、支持 offset/limit，而 shell 文本命令会把观察压成一段普通 stdout。规则不是单纯偏好某个工具，而是在要求每次读取都留下可分页、可引用、可受策略检查的证据结构。

工程纪律

编辑锚点默认要求唯一

old_string exactly once

定向编辑只有在旧文本唯一出现时才自动执行；多处命中必须扩大上下文或显式 replace_all。它把歧义变成失败而非猜测，让局部修改的作用域由可证明的文本身份决定。

工具·多智能体

文件发现不继承 Git 的可见性假设

hidden and ignored are searchable

Glob 会覆盖隐藏文件与被忽略文件，且无斜杠的 * 匹配整棵树而非顶层。能力面比常见 shell 直觉更宽，因此 Agent 必须把模式写窄；这里提醒工具默认可见域本身就是安全与成本边界。

工具·多智能体

检索与阅读形成两阶段证据链

grep first, read context second

专用 grep 负责定位匹配，真正需要上下文时再 read 文件。DSH 将搜索与理解拆开：第一步压缩候选范围，第二步建立可引用证据，避免把截断的命中行直接当成完整语义。

工程纪律

每次命令都必须读取终止状态

check every exit code

stdout 看起来合理并不代表命令成功；提示词要求逐次读取退出码并调查失败。命令执行由此不是“拿到一些文本”就结束，而是输出、状态与后续诊断共同构成一次完整观察。

工具·多智能体

后台作业采用通知驱动而非忙等

no busy polling

运行时会主动通知作业完成，Agent 应在等待期间推进独立工作；最终回答前还要收集仍相关的结果并终止失去意义的任务。异步能力因此带着生命周期所有权，不能只负责启动、不负责收尾。

工程纪律

联网结论必须留下可追溯入口

cite relevant source URLs

Web Search 返回答案与来源列表，最终陈述应把相关 URL 贴近对应结论。检索并不自动等于证据；只有来源被筛选、关联并暴露给读者，外部知识才进入可复核的交付链。

目标机器

跨会话目标默认解除武装

resumed goals are disarmed

目标对象可以跨会话保存，但恢复或 fork 后不会自动继续执行，必须由人类再次表达继续意图并显式 rearm。哲学层（推断）：DSH 把持久意图与当前授权分离，记住目标不等于永久持有行动许可。

工具·多智能体

编排规模必须由需求证明

workflow only for explicit large orchestration

Workflow 被保留给用户明确要求或真正的大规模扇出，一两个委派应使用普通 subagent。能力越强不代表越应默认启用；这里用问题规模与授权来源共同约束编排复杂度。

工具·多智能体

Ralph 用新代理轮次检验持久状态

fresh child, shared workspace

每轮 Ralph 都从没有对话种子的全新子代理开始，只通过共享工作区继承进展。哲学层（推断）：DSH 把可持续性放在环境状态而非单个模型心智里；若下一位 Agent 无法从产物接手，所谓长期自治就没有真正落地。

工具·多智能体

委派默认不阻塞主线

subagent background by default

只有下一步严格依赖结果时才允许前台等待；独立委派应一起启动，主代理继续推进可并行工作。前后台不是风格选择，而是由关键路径依赖决定的调度策略。

人格

文件变更必须回到人类可见交付

mention primary outputs

工具成功写入文件后，最终回答仍需点名主要产物并使用可点击路径。完成不是内部动作发生，而是用户能定位、打开并继续工作的结果；这把执行事实翻译成界面可消费的交付。

安全边界

文件能力由运行时策略限定

workspace-write policy

当前快照允许修改会话工作区与部分平台临时区，但这是一条运行时事实而非 Agent 自行声明的权限。提示词把可写范围显式注入上下文，让文件操作边界可观察、可随会话变化。

安全边界

无人可审批时默认拒绝

approval fails closed

需要批准的动作只能通过已配置的 answerer 请求；没有审批通道就直接失败，而不是把缺席解释为默许。它把授权不可用与授权已授予严格区分，防止自动化环境中的沉默变成权限升级。

工具·多智能体

结构化追问用稳定 ID 闭合回路

stable question id echoed back

答案不仅返回自然语言，还回显问题 ID，使多问题表单可以按身份而非显示顺序关联结果。这个小字段把澄清从一次对话插曲变成可机器匹配的请求—响应协议，便于后续条件分支稳定消费。

工具·多智能体

后台输出区分增量流与最终产物

stream delta vs settled result

流式作业只返回自上次读取后的增量，最终输出型作业则在 settled 后交付结果；每次响应还附带状态标记。DSH 把日志游标、终态结果与进程状态放进同一读取协议，避免重复吞入整段输出。

目标机器

Ralph 轮次之间只传递有界报告

bounded report crosses rounds

新子代理不继承父对话或上一位子代理会话，跨轮次只允许共享工作区和有界结构化报告。这个约束限制了叙事上下文无限膨胀，并迫使每轮把可接力状态沉淀为文件事实与明确摘要。

工具·多智能体

空白子代理必须获得自足任务契约

standalone prompt for blank child

普通 subagent 没有父对话，委派 Prompt 必须重新给出目标、边界与所需证据。隔离节省主上下文，但把知识传递责任转移给父代理；“去做一下”不是有效接口。

工具·多智能体

Fork 继承已完成历史，不继承半成品回合

completed turns only

subagent_fork 能复用既有对话，却以已完成 turn 为一致性边界；当前仍在生成的回合不可见。它避免子代理读取尚未收敛的父代理意图，也提醒调用方：本轮新增约束仍需在委派中显式补充。

目标机器

待办更新采用全量状态替换

entire list replaces previous state

todo_write 没有局部 patch，每次调用都提交完整列表；并行工作可以同时存在多个 in_progress，串行工作则只保留一个。计划工具因此更像声明式状态快照，调用方必须对遗漏项和状态一致性负全责。

安全边界

目标控制权绑定顶层人类意图

goal control needs direct human request

即使目标已存在，修改、暂停与恢复也不能由子代理报告或自动续跑自行触发；只有顶层人类请求能改变这些控制状态。持久目标由此具有状态连续性，但不获得自我续权能力。

工具·多智能体

编排脚本对未知选项显式失败

unknown workflow options fail loudly

Workflow 不会静默忽略看似合理但未支持的 effort、isolation 或 agentType；误用 hook 会直接终止脚本，而不是退化成某种默认行为。严格接口让编排失败在边界处可见，避免多 Agent 系统带着错误假设继续运行。

安全边界

Write 的原语是整文件替换

create or fully replace

写入工具不是模糊的“保存”，而是新建或完整覆盖 UTF-8 文件；既有内容保护主要来自 read-first 策略与 targeted edit 的替代路径。明确原语有助于 Agent 在调用前评估覆盖半径与可逆性。

目标机器

持久目标只能从顶层人类意图取得权威

reject non-human goal authority

DSH 可以从人类的直接请求推断长程目标意图，不要求用户说出固定命令；但工具层会拒绝系统内部或子代理替人类创建目标。自然语言识别可以宽松，权威来源校验必须严格，二者被刻意放在不同层处理。
